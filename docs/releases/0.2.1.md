# 0.2.1

## Fix: several servers crash each other through the shared index (#7)

Every Claude session starts its own server, and all of them open one index database. In WAL mode SQLite maps a shared `-shm` file into memory. When one process re-initialized that file, the other processes failed with SIGBUS in `walIndexTryHdr`, and Claude reported `Connection closed`.

- The index now uses a rollback journal (`journal_mode=DELETE`). There is no shared memory file.
- Each connection waits up to 30 seconds for a lock (`BUSY_TIMEOUT_SECONDS`) instead of failing while another process writes.
- An existing WAL index converts the first time a server opens it while no other process holds it open. Until then, the server logs a warning and keeps working in WAL mode.

Tests: `tests/test_shared_index.py`.

```
 src/legal_workspace_mcp/config.py  | BUSY_TIMEOUT_SECONDS
 src/legal_workspace_mcp/indexer.py | journal_mode=DELETE, busy timeout
 tests/test_shared_index.py         | 3 tests
```
