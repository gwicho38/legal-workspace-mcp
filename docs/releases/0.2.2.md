# 0.2.2

## Fix: the server misses the 30-second handshake limit

Claude Code waits 30 seconds for a stdio server to answer `initialize`. The server built its index before it read its first message. The build hashed every file by reading it. On a workspace of symlinks into OneDrive, about half the files are cloud-only, and each read made macOS download the file first. Startup took many minutes, and every session reported `connection timed out after 30000ms`.

- The startup index build now runs in a background thread on its own connection. The server answers the handshake at once and searches the persistent index meanwhile.
- The indexer never reads a cloud-only file (`SF_DATALESS` in `st_flags`), so it never forces a download. The build summary counts these files as `skipped_cloud_only`. Rows already indexed for such a file stay.
- `workspace_status` reports the build state under `startup_build`.

Tests: `tests/test_startup_responsive.py`.

```
 src/legal_workspace_mcp/indexer.py | is_dataless(), skip cloud-only files
 src/legal_workspace_mcp/server.py  | background startup build, _build_state
 tests/test_startup_responsive.py   | 3 tests
```
